## Scope

This evidence records the dedicated MariaDB 10.11 development/test environment
and verifies that the server supports the UTC session timezone and
`STRICT_TRANS_TABLES` required by the architecture. It does not configure or
verify a Laravel database connection.

## Approved baseline

| Component | Required | Observed | Result |
|---|---|---|---|
| Database server | MariaDB 10.11 | MariaDB `10.11.15` | PASS |
| Listener | Local machine only | `127.0.0.1:3306` | PASS |
| Development database | Separate database | `student_document_management_dev` | PASS |
| Test database | Separate database | `student_document_management_test` | PASS |
| Session timezone capability | `+00:00` | `+00:00` | PASS |
| Session SQL mode capability | Contains `STRICT_TRANS_TABLES` | Enabled | PASS |

MariaDB 10.4 from XAMPP remains only a possible baseline import source. It is
not the active development or test server for this task.

## Installation and local configuration

MariaDB Community Server `10.11.15` was installed as the automatic Windows
service `MariaDB`. The downloaded MSI SHA-256 matched the checksum published
with the distribution:

```text
7a2502de1c4f5ae22d7fcfc1b6718b91e77bfded46ed825a97543f1b2934c1fa
```

The machine-local server configuration binds MariaDB 10.11 to
`127.0.0.1`. `netstat` confirmed that process `mysqld.exe` listens only on
`127.0.0.1:3306`, not on all IPv4 or IPv6 interfaces. This machine-specific
configuration is not stored in Git.

The XAMPP MariaDB 10.4 process that previously occupied port `3306` was stopped
gracefully with `mysqladmin shutdown` before the MariaDB 10.11 service started.
No XAMPP data was deleted.

## Machine-level security follow-up

The local `root` account currently has no password. This is a machine-level
security follow-up and does not change the P0-02 server capability result. The
application must not connect as `root`. Dedicated application accounts must be
created and secured before Laravel database credentials are configured.

## Database separation and capability check

The following two schemas were created independently:

```text
student_document_management_dev
student_document_management_test
```

The validation session successfully applied:

```sql
SET SESSION time_zone = '+00:00';
SET SESSION sql_mode = CONCAT_WS(
    ',',
    @@SESSION.sql_mode,
    'STRICT_TRANS_TABLES'
);
```

The observed session values were:

```text
session_time_zone: +00:00
session_sql_mode: STRICT_TRANS_TABLES,ERROR_FOR_DIVISION_BY_ZERO,
                  NO_AUTO_CREATE_USER,NO_ENGINE_SUBSTITUTION
strict_trans_tables_enabled: 1
```

This proves server capability only. P1-02 must configure each application and
test connection, and its integration check must fail when either required
session setting is absent.

## Commands actually run

The relevant installation and final verification commands included:

```powershell
Get-FileHash .\mariadb-10.11.15-winx64.msi -Algorithm SHA256
msiexec.exe /i .\mariadb-10.11.15-winx64.msi
Get-Service -Name MariaDB
& 'D:\PHP\mysql\bin\mysqladmin.exe' --protocol=tcp `
    --host=127.0.0.1 --port=3306 --user=root ping
& 'D:\PHP\mysql\bin\mysqladmin.exe' --protocol=tcp `
    --host=127.0.0.1 --port=3306 --user=root shutdown
Start-Service -Name MariaDB
netstat -ano -p tcp
& 'C:\Program Files\MariaDB 10.11\bin\mariadb.exe' --version
```

The database creation and capability SQL was run through the MariaDB client in
an interactive PowerShell window. No database credential was passed through a
command argument, written to the evidence, or committed.
