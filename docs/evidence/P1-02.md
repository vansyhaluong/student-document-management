## Scope

This evidence records separate least-privilege MariaDB application accounts for
development and testing, Laravel connection session settings, safe environment
templates, and test isolation. It does not add business migrations, create the
P1-05 destructive-test database guard, or begin P1-03.

## Credential handling

Two independent random passwords were generated in memory. Their values were
never printed or written to the repository. They are held in separate
User-scope environment variables for the local machine. The repository stores
only a blank `DB_PASSWORD` placeholder and the non-sensitive test secret
variable name used by the test bootstrap.

No `.env` or `.env.testing` file was created. No credential, password,
connection string, private import path, or private data was written to this
evidence.

## Test isolation

`phpunit.xml` selects MariaDB, the dedicated test database, and the dedicated
test account. The first bootstrap implementation normalized conflicting parent
process database values to the test target without rejecting them. Final review
correctly identified that behavior as pinning, not fail-closed validation.

The final bootstrap validates existing process-level connection, host, port,
database, and username values before writing the authoritative test
environment. Missing or matching values are allowed. A conflicting value
throws an exception that names only the variable and the required test
environment.

Regression tests cover missing overrides, matching test overrides, a
development database override, a development username override, and password
non-disclosure. Separate process-level adversarial runs confirmed both
conflicts stop PHPUnit before Laravel connects and neither output contains the
test password.

This pinning is limited to P1-02 connection isolation. P1-05 remains responsible
for the broader test bootstrap guard that protects destructive test setup.
