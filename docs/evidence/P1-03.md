## Namespace mapping

| Namespace | PSR-4 path | Ownership |
|---|---|---|
| `App\Enums` | `app/Enums/` | Approved finite application/domain values |
| `App\Exceptions` | `app/Exceptions/` | Domain and application exceptions |
| `App\Http\Requests` | `app/Http/Requests/` | HTTP authorization, validation, and light normalization |
| `App\Services` | `app/Services/` | Use cases, business rules, and business transactions |
| `App\Repositories` | `app/Repositories/` | Persistence contracts and implementations |
| `App\Policies` | `app/Policies/` | Server-side action authorization |
| `App\Support` | `app/Support/` | Cohesive shared application infrastructure |

Composer already maps `App\` to `app/` in `composer.json`; no autoload mapping
change is required. No PHP marker type is introduced, so reflection checks are
not applicable. Composer autoload generation and strict PSR validation verify
the existing mapping.

## Dependency rules recorded

- Requests do not persist data, open transactions, or coordinate workflows.
- Services own business rules and transaction boundaries, depend on repository
  contracts for persistence, and do not depend on HTTP input or responses.
- Repositories encapsulate persistence and do not authorize actions, decide
  transitions, own business transactions, or depend on HTTP.
- Future repository interfaces belong in `App\Repositories\Contracts`; future
  Eloquent/Query Builder implementations belong in
  `App\Repositories\Eloquent`.
- Generic `BaseRepository` and `CommonService` abstractions are prohibited.
- `App\Support` is limited to cohesive shared infrastructure and is not a
  miscellaneous helper directory.
